# Daily Energy Law Watch (Ukraine)

## Мета

Щоденний автоматизований моніторинг офіційних українських державних джерел у сфері енергетики, будівництва, податків та суміжної регуляторики. Збір, фільтрація, аналіз публікацій та генерація рекомендацій для юриста щодо найважливіших тем для бізнесу.

## Розклад

- **Запуск:** щодня о 08:30 (локальний час)
- **Вікно перевірки:** 24–72 години від попереднього запуску
- **Вхідна точка:** `execution/run_energy_watch.py`

## Щоденний потік (покроково)

1. Завантажити лог оброблених публікацій (`data/processed_log.csv`)
2. Для кожного джерела:
   a. Скрапити список нових публікацій (24–72 год)
   b. Відфільтрувати за ключовими словами
   c. Перевірити дедуплікацію через лог
3. Для кожної нової релевантної публікації:
   a. Завантажити повний текст
   b. Визначити тип (закон / постанова / наказ / роз'яснення / новина / інше)
   c. Підготувати картку
4. Згенерувати **Секцію A — Digest** (структурований огляд)
5. Оновити лог
6. Згенерувати **Секцію B — Article Opportunities** (теми для статей)
7. Якщо є нові необроблені матеріали → **Секцію C — Content Skeleton**
8. Зберегти результат у `data/digests/YYYY-MM-DD.md`

## Формат виходу

### Секція A — Digest

Для кожної публікації:
1. Назва
2. Джерело
3. Дата публікації
4. Посилання
5. Тип
6. Стенограма / повний текст
7. Головний висновок (1–3 речення)
8. Чому важливо для бізнесу (3–6 булетів)
9. Що перевірити юристу (чеклист 3–7 пунктів)

### Секція B — Article Opportunities

5–10 тем із зазначенням: ЦА, біль, практичні поради.

### Секція C — Content Skeleton

Для 1–3 найважливіших нових матеріалів:
- Ключові тези (8–15 булетів)
- План статті (hook, контекст, вимоги, ризики, дії, FAQ, висновок)
- Міні-резюме для клієнта (до 600 знаків)

## Правила дедуплікації

- Якщо `url` або `unique_id` вже є в Log зі статусом `processed` → пропустити
- Якщо публікація дублюється між сайтами → обрати найбільш "первинне" джерело:
  - Рада — для законів
  - КМУ — для постанов/розпоряджень
  - Відомства — для роз'яснень

## Guardrails

- Працювати **тільки** з джерелами зі списку
- Мова результатів: **українська**
- Посилання: прямий URL на конкретну публікацію
- Не вигадувати фактів — якщо даних немає, прямо зазначити
- Якщо транскрипції немає → позначити: **[Транскрипція відсутня — зроблено виклад]**
- AI-аналіз (секції B, C) виконується через Anthropic API (ключ у `.env`)

## Файлова структура

```
data/
  processed_log.csv          — лог оброблених публікацій (персистентний)
  digests/
    YYYY-MM-DD.md            — щоденний дайджест
tmp/
  raw_pages/                 — кешовані HTML-сторінки (тимчасові)
```

## Відомі особливості та обхідні шляхи

- **Telegram:** використовуємо веб-превʼю `https://t.me/s/verkhovnaradaukrainy` (не потребує API-токена)
- **NERC:** сайт може бути повільним — таймаут 30 сек, 2 ретраї
- **Rada:** новини можуть мати вкладену пагінацію — перевіряти перші 2–3 сторінки
- **KMU:** має RSS-фід — використовувати як первинний метод
- **Tax.gov.ua:** структура може змінюватись — є fallback-селектори

## Автозапуск

Для щоденного запуску додати у crontab:
```
30 8 * * * cd /path/to/project && python execution/run_energy_watch.py >> data/cron.log 2>&1
```

Або використовувати `schedule` бібліотеку всередині `run_energy_watch.py --daemon`.
